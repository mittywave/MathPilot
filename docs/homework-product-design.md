# 作业系统产品与交互原则

## 产品目标

作业批改是工具箱里的独立工具（`/tools/homework`），学生档案的“作业”页签列出每位学生的作业。没有学生端：学生拍好的照片或 PDF 由老师上传。作业有两种来源：一是学校发的作业，老师直接上传批改；二是老师在快速排版里把练习“布置给学生”，题目和答案先存进作业，学生交上来再按这份清单批改（见“布置作业”）。已布置的校内作业只判正确或错误，空白、涂掉和看不清的作答计错；其他作业看不清或无法核实的题目单独待处理。

作业总表以状态、学生、去重作业标题、结果和上传时间分列，整行进入详情。上传页面左侧选择学生、课程和写入范围，右侧接收作业及参考答案。URL带有效studentId时保留学生来源，面包屑姓名回到该生“作业”标签；工具箱默认选中的学生不改变来源。批改详情始终通过学生姓名回到该档案，刷新、配图校对、新版本等操作集中在面包屑右侧菜单；仅已有可下载国际卷报告时显示报告下载，保留TeX入口。

批改本身只产出这份作业的批改记录。写入学生的内容是三个独立模块，上传时按作业逐项选择，由 `lib/server/homework-outputs.ts` 统一调度：

| 选项 | 模块 | 默认 |
| --- | --- | --- |
| 加入学生错题本 | `homework-wrong-book.ts` | 开 |
| 生成错题报告 | `homework-reports.ts` | 开 |
| 计入定档（知识点与题型） | `homework-capabilities.ts` | 开 |

选项保存在作业上（`homework_assignments.outputs_json`），同一作业的新版本沿用；发布、教师修正、补全配图后，只重新运行已选的模块。直接上传的新作业默认“计入定档”，批改详情页可以事后切换；布置的作业总是计入。旧作业和缺少该字段的旧数据维持原来的关闭含义，不批量修改，由老师自行决定。

事后打开“计入定档”会为这份作业全部已发布的提交补写证据，证据日期使用各次提交的 `COALESCE(submitted_at, created_at)`，近30天、近90天和学情报告的时间筛选因此仍按原作业时间计算；关闭则移除整份作业的证据。选项和全部证据在同一数据库事务里提交，失败时一起保留原状；重复打开不会重复计数。同一作业有正在批改或发布的提交时暂不可切换，即使操作来自旧版本。切换只更新定档，不重新批改、不生成报告、不改变错题本。

## 界面原则

学生档案同时提供班级分组与独立学生入口。班级可以为空，创建时可以勾选已有学生，班级页可添加已有学生或新建学生。每位学生沿用现有班级字段，只属于一个班级；未填写班级的学生为独立学生。现有班级/年级名称自动沿用为班级。转班、移出班级、重命名或删除班级仅改变分组，保留学生档案、作业、批改和错题；删除班级后原成员成为独立学生。所有班级和成员操作按老师账户隔离，同一账户不能有同名班级。

班级页的“布置作业”复用快速排版历史与智能组卷记录，选择已有练习后默认选中当前全班。快速排版的“布置给学生”也能按班级全选，并允许逐个调整或混选独立学生；同一学生不会因重复选择而重复接收。一次最多布置给 200 位学生，与学生档案上限一致。作业沿用现有逐学生创建流程，每位学生独立提交、批改、订正和归档。接收名单以本次布置时勾选的学生为准，之后增减成员不追溯已布置作业。

- 一个页面、一个状态、一个主要操作。
- 先结论、后证据；先当前任务、后历史信息。
- 能省的按钮就省，低频操作收进折叠区、弹层或更多菜单。
- 按钮横排、文案简短，不用竖排文字，不依赖图标猜含义。
- 作业批改列表、学生作业行和快速排版历史已经单独显示学生时，标题仅去掉开头重复的学生名及其分隔符；同名作业以第二行开头的上传日期区分。存储标题和打印练习保留学生名，不修改智能组卷的标题生成规则。
- 上传保持“放入照片或 PDF—提交—查看结果”的单一路径；照片按原样批改，不做纸张检测或透视校准。放入作业的入口和录入题目一样：直接粘贴（⌘V，截图或复制的文件）、拖进入口，或点击入口从文件夹选择，照片和 PDF 可以一次放入多份，PDF 按页拆开；已有页面时入口缩成一行，继续添加。作业原件、参考答案与补充材料中的 PDF 共用文件转录的页面读取流程，按扩展名或 PDF 文件类型识别，不经过 Word 结构导入。
- 掌握情况只用于帮助理解，不展示伪精确分数；必须同时提供清晰的文字结论。
- 校内批改页的结果分布只显示“正确 / 错误（待订正）/ 已订正”：一题里有任一小问或步骤未完全正确，整题就按错误显示，历史“部分正确”也并入错误，不再单列黄色分布。布置的作业按整份题目在全部已发布上传中的最新结果统计；较早做错、后来已完全正确的题单列已订正，不能只统计当前打开的那次上传。比例条只分配已确认题目的三种状态；未交和待核实另行注明，不算错，也不算订正成功。IGCSE / A Level 继续保留正确、部分正确、错误、待处理及步骤分。已布置的校内作业只判正确或错误，空白、涂掉和看不清的作答计错；其余作业需要复核、看不清或判定待核实的题列为待处理；错误或历史部分正确的题，如果没有老师已有判定，且缺少已核实的参考答案，也待处理。老师已有判定可免参考答案，但不能覆盖“需要复核”的状态。标题“需要改进”和列表“错”均为已判定的部分正确加错误；已归档错题单独标明，不等同于错误总数。
- 批改详情、作业批改列表、学生作业和布置作业每天的进度共用上述口径；识别到父题号时保留它下面已有的小问。待处理区展开列出对应题号，可直接定位原卷和逐题证据。这里仅统一显示与汇总，不改变批改、发布和错题归档规则。

## 性能与无障碍

- 主要操作最小触控高度为 40px，桌面和 390px 移动端均不得产生页面级横向滚动。

## 中国课程知识图谱

知识图谱采用“课程节点—教材定位—题库题目—学生证据”的单一数据链路：

1. `cn-math-junior-v1` 提供稳定知识节点、父级领域、年级阶段和有向前置关系。
2. 人教版、北师大版和苏教版映射到同一知识节点；教材版本只是定位层，不复制三套知识图谱。
3. 题库题目和作业题目保存稳定 `taxonomyKeys`，AI 生成的自由知识标签仅用于辅助映射和人工校正。
4. 批改结果通过题目节点生成学生证据；无法辨认的拍摄问题不进入知识图谱。
5. 教师端展示完整前置路径、题号证据、关系依据和教材定位。

数据与可视化运行时分离：`data/china-math-taxonomy.v1.json` 是图谱 v1 种子，之后的版本由教师在 `/knowledge-graph` 编辑并发布到 D1（见 `docs/knowledge-graph-design.md`）。校验器检查稳定 ID、引用完整性和 DAG 无环；Canvas 只按年级和课程领域投影节点，不把业务分类写死在绘图代码中。

V1 当前是七至九年级数学课程骨架。三个教材版本已建立框架级映射，但具体册次与章节仍标注为“待校准”；未经过教材目录核对前，不得将其展示或宣传为精确章节定位。

## 已完成作业直接批改

老师在学生档案或作业记录中选择“上传作业并批改”，选择学生并上传已完成作业。支持图片和 PDF，学校作业原件、参考答案均可选。学校作业原件入口位于学生作业与参考答案之间，与学生作业复用同一个虚线上传框，支持粘贴、拖入、点击选文件以及页面预览、排序和删除；接收空白试题或练习的图片和 PDF（按页拆开，最多 30 页），未上传不影响提交；独立保存为作业的题目材料，批改详情可逐页查看。同页有多个上传框时，粘贴只进入当前聚焦的上传区域；未聚焦某一区域时默认进入学生作业，不会同时加入两处。任一上传区仍在读取文件时不能提交。先从学生页面确定实际题目清单，再用原件核对同一题的印刷题干、选项、配图条件与分值；按题号和内容匹配，不假定两份文件页码一致，不加入仅见于原件的题，不用原件空白覆盖学生作答、老师标记及裁图坐标，也不把原件当参考答案。材料上传中断后从已成功的页继续，提交草稿建立后锁定材料选择，避免重试混入不同文件。原件保留，作业题干识别、独立参考解答、参考解答校验和学生作答判断分开处理。仅完全错误归入当前错题本；部分正确只保留在作业记录，待补图或待核实不产生错题及负面学习证据。

校内作业每页练习各自编号，题目以“起始页码-印刷题号”标识，显示为“第 5 面 第 3 题”；有小问的题每个小问单独成题（5-3(1) 显示为“第 5 面 第 3 题 (1)”），题干带上大题的公共条件，各自判定、各自进入错题本。老师已经批改过的题按作答旁的批改符号判定：对勾为正确，半对勾为部分正确，叉或圈出答案为错误；这些题不转录学生答案，不让 AI 改判老师的符号；正确题不再求解，错误和部分正确题必须另行生成并独立核验参考答案，只展示正确答案，不写学生过程转录。明确引用前一小问条件时，解题与核验复用该小问已有的印刷题干和配图条件，不传入学生作答；核验检查答案的数学正确性，不因校内最终答案未附推导而拒绝。题干不完整或答案无法核验时明确保留待补充原因，不编造答案。判错题仍可按老师的叉进入错题本。没有批改符号的题由 AI 解题并判对错，只保留结论和参考答案的最终结果，不写解析、步骤分析和反馈；学生作答仅提取判题必要的最终答案或极短摘要，不逐行转写过程。错题本“作业批改记录”只展示原答图片，没有裁图时回退到原卷页面。分栏批改页直接在左侧查看原卷；校内作业右侧展开后展示参考答案，不重复展示题干、配图和学生作答文字或图片，老师判对的题明确说明无需补充参考答案；错误和部分正确题缺少可用答案时进入现有待处理流程，支持补齐历史记录。IGCSE / A Level 继续保留评分所需的作答过程。

原卷印刷了分值（如“(5 marks)”“（5分）”）时按步骤给分：方法分与答案分分开，接受等价表达和有效替代解法，同一错误不重复扣分。满分随题目识别保存，老师可补填或修正满分与得分，得分决定结论（满分为正确、0 分为错误、其余为部分正确）。总分的分母始终是整份作业；仍有待处理题时只显示已确认得分和待定题数，不显示得分率。没有印刷分值的作业不显示分数。写失分反馈时（IGCSE / A Level），写清哪一步失分、涉及的知识点或步骤和订正动作；报告建议附可观察的完成标准，措辞只描述本次作答，不归因粗心或态度，不推断用时与考试等级。

### IGCSE / A Level 批改

上传时选择课程：“校内数学”沿用上面的流程；“IGCSE / A Level”按 Alevel 项目已确认的批改规范处理。公立小学、公立初中的专门规则暂未制定，目前都走“校内数学”。

- 按印刷分值的粒度拆题：单独印了分值的小问各成一题（如 3(b)(ii)），分值只印在整题末尾时整题为一题。题干保留英文原文，并带上本大题的公共条件和配图条件。每次上传一份试卷，题号保持印刷题号；同一题号在两页都被识别为起始页时，说明有页面识别错误，系统丢弃这些页的识别结果并重新识别。
- 参考解答写成本小问的评分要点（方法分 M、结果分 A、独立分 B，FT、AG 说明），分值合计须等于印刷分值。有 mark scheme 时按其得分点转录，没有时按考试局惯例拟定，核验时同时检查分值合计。
- 逐个得分点给分：结果分只在对应方法分已得时给，沿用自己前面的错误结果时按 FT 继续给分，show that 题须完整推导，未指定时按 3 位有效数字、角度 1 位小数判精度，接受等价形式和有效替代解法。逐点结论（如“M1 ✓”）留给老师核对；给学生和家长的反馈用中文，不出现评分代码。
- 空白和看不清的作答记 0 分，计入满分；看不清的小问仍列为待处理，补交清晰照片后可重批。缺页、题意不完整或参考解答未通过核验的小问不计分，得分率待全部定分后给出。
- 批改报告由家长和学生共读，结构沿用 Alevel 已确认的版式：成绩概览、本次学习表现（引用题号，优先改进 2—3 项）、按大题汇总的分题成绩、逐项失分分析（失分事实、知识与能力、正确思路、订正动作，覆盖每一处失分）、按优先级的练习建议及完成标准。看不清记 0 分的小问只说明评分事实和补做动作。报告页的主要操作是“下载报告 PDF”，由本机 Tectonic 排版；不能排版的设备可下载自包含的 TeX 源文件。

题干只保留原卷印刷的文字，“如图”保持原样，不用文字补写图形内容。错题快照去除独立的组别标题和重复大题号，保留本小问编号、公共条件、公式、选项与段落；公式和表格保持可编辑。平行符号、根指数等必须保留数学含义，Word 中不能把根指数变成正文，也不能因比较符号生成损坏文件。原始识别记录继续保留来源信息。

### 作业归档配图规范

| 项目 | 要求与验收 |
| --- | --- |
| 来源与归属 | 只从题目实际所在页取图；每张已存裁图同时记录源页面资源 ID、页码、裁剪框。旧图源不一致时不能直接复用。配图定位结果必须与本次完整题号清单一致，重复或多出题号即拒绝。已撤回的错页题号不参加配图校对。 |
| 内容边界 | 题图包含图形及全部点名、数字、刻度、箭头、图号；排除题干正文、邻题、页眉页脚和独立的学生计算。不能把有墨迹的文字区域当成题图；没有可靠图形笔画的候选框保持待核对，不能冒充“无配图”。 |
| 小问共用图 | 题组公共配图提供给每个依赖它的小问；仅属于另一小问的图不混用。漏图校对应检查整道题的公共区域，不能只看该小问附近。 |
| 选项与表格 | 图形选项整体保留 A/B/C/D 标号；纯文字选项仍是文字。表格、算式转录为可编辑结构，不作为题图截图。 |
| 手写覆盖 | 优先排除图外独立手写计算。图内与印刷线条交叠的手写坐标、辅助线、答案或批改痕迹忠实保留；不得猜测擦除、补画或把重绘图冒充原图。若必须得到纯净图，应补充空白原卷后重新定位。 |
| 作答证据 | 学生整页原答与答案局部图只放在批改证据中，不用它们替代题图。网页题卡和 Word 均不附加手写覆盖说明；识别元数据仍保留供内部核对。 |
| 排版 | 按原比例显示，四周留少量白边；宽路线图、数轴和多图组合放在题干下方。不得拉伸、裁掉标注或把文字缩到无法阅读。网页与 Word 使用同一份题干和裁图。 |
| 重校对与缓存 | 批改记录页的“校对原卷配图”可重查已有图和空图列表，而不只是补缺。定位失败不覆盖原记录，并明确报告失败页。校对成功同步更新题目、识别缓存与当前错题快照，避免后续重试重新带回旧图；不改变批改结论。 |

像素笔画检查只能拦截明显的纯文字误裁，不能代替语义归属和视觉检查。发布前应对照原页检查图与题是否一致、标注是否完整、图内手写记录是否准确，并在桌面、窄屏及 Word 逐页验收。图中解题所需的条件另存为供解题使用的 `figure_notes`，不能把这些推断说明写进题干。历史校对移除模型补写的图形说明时，只删除可对齐的原文引用，不重写题意。

待处理题可以补图或由老师补充题干、参考解答并确认判定。重处理只更新待处理题；补图前原件单独保留。每个批改项是一条错误发生记录，重试和重复发布不累计次数，同题的新提交版本可以累计。教师修正后按有效错误发生记录重新计算，历史手动记录和被撤销的记录保留在历史区。只有开启“计入定档”的作业才写入图谱能力证据；批改结果页不加载学习图谱。

批改结果的原卷与逐题详情在桌面端使用可拖动分栏，整体宽度与上方整份作业、结果统计卡片保持一致，居中对齐，各自在固定高度内独立滚动；分隔条支持方向键调整宽度，双击恢复默认比例。点击原卷标记打开并定位详情，展开详情定位并突出对应原卷标记。逐题证据标题随详情滚动，不置顶遮挡题目。每题折叠标题保留题号与判定结果，老师批改时显示来源，不显示模型置信度。窄屏使用上下独立滚动区域。

## 布置作业

快速排版里打开的任何资料（Word 练习、组卷篮、智能组卷的方案）都可以点“布置给学生”，选一位或几位学生。学生档案的“作业”页签右上角只有“布置作业”：列出智能组卷给这位学生组好、还没布置的卷（按题目 ID 从题库取题，已删的题跳过），点一份就打开同一个“布置给学生”弹窗，默认选中这位学生，布置后列表里直接出现这份作业；没有可布置的卷时提示去智能组卷新组一份，Word 练习仍在快速排版里布置。弹窗最下面是“学校发的作业 · 上传作业”，打开作业批改的上传页并选中这位学生，学校发的作业从这里直接批改。每位学生得到自己的一份作业，状态是“待提交”：

- **题目和答案在布置时就存进作业**（`assignment_questions.source_json` 存题目原样，作业的 `sheet_json` 记任务分组和来源的快速排版记录 `recordId`；只记本人的记录，学生档案据此知道哪份卷已经布置过，记下来源之前布置的作业没有这条，它的卷仍会出现在“布置作业”里）。题库里的题按题库原题复制；Word 里读出的题按读出的样子保存，图片存成只有这位老师能看的素材，知识点按题干和解析里“本题考查……”自动对到图谱。之后改题库或删排版记录都不影响已布置的作业。
- **查看作业原题**：进入已布置的作业后，“整份作业”右上角的“查看原题”展开布置时保存的题目，包含题干、选项、公式和配图，复用题库的 `Question` 数据格式和题目展示；多天任务按原分组显示，各天题号从 1 开始。有解析的题目下方提供“查看解析 / 收起解析”，每题独立展开已有答案和解析，复用题库的 Word、公式及解答图渲染；没有解析时不显示按钮，也不生成解析。待上传、批改中及已发布时都可以查看，点击“收起原题”恢复；原题来自作业快照，不随当前题库改动，也不重新识别或批改。
- **排版历史自动备注接收人**：历史条目下显示“已布置给：学生名”或“已布置给：班级（学生名……）”，同一班的实际接收人归在一起；只为某位学生组好卷尚未布置时不显示。备注从同一老师的有效作业按来源 `recordId` 读取，重复布置及订正上传不重复列名；取消作业后移除对应接收人，仍有其他有效作业时保留。姓名和班级取学生档案的当前值，不据当前班级成员推测谁收过作业；旧作业未保存来源时不按标题猜测。布置弹窗关闭、打开历史或窗口重新获得焦点时刷新，较长名单省略显示并可悬停查看完整内容，不改变历史的编辑时间排序。
- **题号就是纸上印的号**：不分组是 1、2、3…；智能组卷按天分组，每天从 1 开始，记作 D2-3，显示为“第 2 天 第 3 题”。
- **天数是任务量**：“3 天打卡”表示第 1、2、3 天的三份任务，不要求连续三天完成。布置时不选择或预设日期，也不从布置日期推算各天日期；旧作业保存过的预定日期不再使用。
- **各天任务的状态与提交日期**：一天里有题出现在某次已发布的上传里就算开始提交，提交日期取最早找到它的那次实际提交时间；全部题都找到是“已交”，只找到一部分是“已交 N/M”，未提交的任务只显示“未提交”。不显示“今天交”、到期或逾期提示；未交的题不算错、不进错题本。可以隔天提交，也可以一次提交多天的任务，订正重交不覆盖首次提交日期，每次上传仍各自保留实际提交日期。
- **首交成绩固定**：“整份作业”标题下的对、错数量和每天标题下的“首交对 N/M”，按每道题第一次出现在已发布上传中的判定计算，后续学生订正或重做不覆盖。分次补交从未提交过的题时，将新题的首次结果加入；新一天首次提交也加入它自己的成绩。复用保存首次提交日期的汇总过程，额外返回各天的 `firstAttempt` 派生统计，不新增数据库字段。当前题号颜色、三种状态分布、是否已交齐和右侧“去订正 / 已订正 ✅”继续按最新结果计算；例如首交对 5/10，订正后仍显示首交对 5/10，同时 5 道原错题显示蓝色已订正。教师在原上传中纠正误判属于修订原始评分，按修订后的首次记录显示。
- **只判正确或错误**：已布置的校内作业不设“待补图”结果。题目已定位后，只有完整正确才算正确，部分正确、空白、被涂掉或无法辨认的作答都算错误，原卷标红叉，计入错误数和订正范围。旧上传中的部分正确、待补图与待核实结果在读取时沿用这套规则，原始存档保留；已订正的颜色仍按历次结果推导。修正判定只提供“正确 / 错误”，不提供补图流程。题目或标准答案未就绪时属于批改失败，先解决处理问题，不发布猜测结果。
- **分次交**：学生交来多少就上传多少（照片或 PDF）。识别时把这份作业的题目清单交给模型，只找清单里的题，按页眉的“第 N 天”和题号对应，看不清时按题干内容对照；清单外的题和草稿不算，含小问的题整题算一项。识别不转录题干、不裁配图，题目内容始终是布置时的样子。批改时直接用存好的答案判对错，不再另行解题；布置时没有答案的题照常先解题、核验再批改。
- **整份作业的结果**：每道题取最近一次批改到它的上传里的结果，还没交的题显示“未交”，不算错。作业页顶部的“整份作业”写着任务天数和题数，按天列出每道题的格子；已确认的题只分正确、错误（待订正）、已订正，与下方统计条、图例共用完全相同的绿色、砖红色、蓝色实心底色，绿色沿用原统计条的正确色。待处理和未交用中性灰，不混进三种已确认结果。每天的标题下只写实际提交日期和状态，如“10.13 提交 · 首交对 6/10”“10.16 提交 · 已交 8/10 · 首交对 5/10”“未提交”；点格子定位到那次上传里的批改证据；“继续上传”新开一次上传，交齐后按钮变成“再上传一次”（订正或重做）。每次上传各自保留原件和批改记录，错题本的错误次数沿用“同题的新提交版本可以累计”的规则。
- **点击每天标题查看**：“整份作业”左侧的每天标题可点击，也可用键盘进入；点击后在本页查看当天的实际提交日期、首交成绩、最新批改分布、原卷标记和逐题详情。分次补交、订正涉及多次上传时，各题仍取最新已发布结果，原卷和题目注明所属第几次上传，并提供原上传详情入口；题号格子可定位当天详情。未提交的天显示暂无原卷与批改记录。用“返回第 N 次上传”恢复原来的上传详情。复用现有批改记录接口，按需读取，不重新批改、不修改提交记录。
- **按天订正**：每一天最右侧显示订正状态；当天有已确认的错题或部分正确题时显示红色“去订正”按钮，且上一份上传已发布时才可点击；当天全部题目都已确认正确、其中有过错题时显示绿色“已订正 ✅”，原本全对则显示绿色“无错题 ✅”，完成状态不可点击。未提交、未交齐或仍有待核实题目且没有已确认错题时，保留灰色“订正”，不提前显示完成。点击“去订正”后复用新一轮上传，显示本次错题题号，支持照片和 PDF，只识别、批改所选那一天当前的错题；其他天、原本正确的题及本次没上传的错题保留原结果。上传范围复用已有的 `reprocess_question_ids_json`，刷新后仍保留，不新增数据库字段。没有错误历史的正确题是绿色；曾在较早上传中做错、最新批改已正确的题是蓝色“已订正”；订正后仍错或部分正确的题保持红色。待核实的订正沿用待处理状态，不提前显示订正成功。颜色由已发布的各次结果推导，原始错误、首次提交日期和上传记录继续保留，教师在同一份上传里修正误判不算学生订正。
- **打卡任务按天上传**：多天的布置作业在学生档案的作业列表里标为“打卡任务”，行下逐天列出标题和提交状态；没交齐的那天右侧有“上传这天”，新开一次上传，只识别、批改这一天还没交过的题，上传页标题写“上传第 N 天的作业”并列出本次题号。作业页的“整份作业”里也一样：没交或没交齐的天有“上传这天”，交过的题才有订正按钮，不再给没交的天显示点不了的灰色“订正”。范围同样复用 `reprocess_question_ids_json`；已有待上传记录时直接改成所选那一天（“继续上传”则改回整份），不另建上传。
- **一次只批改一份上传**：同一份作业最新的上传还在批改时，“上传这天”“去订正”“继续上传”不可点，悬停说明要等第 N 次上传批改完或停止批改。最新的上传处理失败时不再卡住：点这些按钮会先确认“第 N 次上传处理失败。放弃这次上传，改为……？”，确认后失败的那次上传让给新的这次（回到待上传、换成新范围，原页面清除）。出过结果后重新批改失败的上传不放弃，提示先重新批改。上传记录里失败或批改中的那次会写明“处理失败”“批改中”，从其他上传页可以直接“去处理”或“查看批改进度”。
- **停止批改，重新上传**：传错页面时，批改进度区有“停止批改，重新上传”（处理失败时叫“重新上传”），确认后这次上传回到待上传，清除它已有的批改结果和传过的页面、PDF 原件，重新选页面提交；上传范围（某天、订正题）保留。仍在运行的批改看到上传已不在批改中，就不再写入结果，也不会把它改成处理失败。出过结果的上传（补图重批、补全页面）没有这个按钮。
- **传错页面立刻说明**：所有页面都读完、却没有一页有这份作业的题时（例如传成了别的学生、别的作业），重试也只会得到同样结果，所以直接标记处理失败，不再自动重试三次、也不显示“无需操作”。批改进度区逐页写出原因（如“本页内容为‘Eric day1 错题’，不属于这份作业”），布置作业的页面标“无本作业题目”而不是“空白页”；这时只给“重新上传”，不给重新批改。
- **写入学生**：布置的作业固定写入错题本和定档（知识点证据），不生成单份的错题报告。错题本里的题是布置时的原题（题库排版、配图、解析都在），附学生原答截图。智能组卷再给这位学生出题时，避开已经布置给这位学生的所有题库题。

学生档案的“作业”页签按布置或上传时间列出这位学生的全部作业，每份作业只显示总标题、提交进度、任务天数、题数和对错汇总，不在列表中展开每天的具体内容、提交记录或逐题预览。布置的作业显示“未提交”“已交 1/3 天”（只统计全部题已提交的任务，不分天的是“已交 8/12”）或“已交齐”；不分天的作业提交后另写实际提交日期。上传批改的作业显示“已批改”。对、错、待处理用一条比例条表示，点作业标题行进入作业页，再查看每天的任务、首交成绩、逐题批改结果并上传；不分天且没交齐的作业右侧保留“上传作业”。页签顶部有未交齐的作业时写“N 份作业还没交齐”。作业列表接口仅提供汇总数据，逐题结果由作业详情读取。

尚未交齐的布置作业在每行最右侧显示独立的小红色垃圾桶图标（14px 图标、24px 点击区域，无文字和边框），提供“取消作业”的悬停提示和无障碍名称，确认框列出学生和作业名称。取消整份作业（含全部打卡天数）复用已有的 `archived` 状态，从学生作业列表和作业批改列表移除，不再计入未交齐或“作业中”；其他学生各自的同名作业不受影响，对应智能组卷方案可重新布置。已有上传原件、批改结果、错题和定档证据保留，原批改详情链接仍可查看。批改中或待发布的作业需先停止或完成批改再取消；已取消作业不能继续上传、订正或批改，旧队列消息也不再处理它。

## 学生档案 · 定档

顶部导航“学生档案”旁复用组卷篮的数字角标，显示当前老师正在批改的作业份数（已提交、处理中），同一份作业只计一次；待上传、已完成、失败和待人工处理不计入，没有批改任务时隐藏。角标在各页面均显示，页面可见时每 4 秒更新，回到窗口时立即更新；读取暂时失败时保留上次成功的数字。计数复用 `/api/submissions?count=grading`，只读汇总，不加载批改详情，不改变侧栏“作业中”的未交齐口径。

学生档案侧栏显示“学生 · N”和一个新建入口，每位学生显示圆头像、姓名和班级；只有非零错题数才显示“错题 N”，不再放没有含义的数字。“作业中”标志只统计老师布置给学生的作业：有未交齐的打卡或其他布置任务、对应上传尚未发布（含待上传、批改中、失败待重试），或布置作业仍有待处理题目时显示；全部交齐且批改处理完成后隐藏。直接上传的历史批改记录不触发标志，即使其中有待处理题目。标志复用现有学生作业记录，进入学生档案、切换学生读取作业、布置新作业以及窗口重新获得焦点时更新，切换页签仍保留。头部去掉卡片边框，一行显示52px头像、26px姓名，以及班级、错题数和备注首句，完整备注保留在悬停文字及编辑档案中；右侧保留同标签打开的“智能组卷”和三点菜单。四个标签页保持“作业 / 定档 / 学情报告 / 错题本 N”；作业页顶栏只有“布置作业”一个操作：弹窗里列出给这位学生组好、还没布置的卷，最下面是“学校发的作业 · 上传作业”，学校发的作业从这里上传学生拍好的照片或 PDF 直接批改；列表第二行写任务天数和题数，提交日期只取实际记录。错题本复用吸顶筛选条，去掉重复解释收录规则的说明。头部作业总数和最近上传时间不在本次范围，不增加接口字段。

当前学生和标签页同步到地址栏，刷新、进入智能组卷后后退，都恢复到离开时的学生和标签。切回题库或组卷篮时清理学生路径参数。从学生出发的智能组卷、批改和上传都带学生标识；上传或批改详情中的姓名面包屑回到这位学生的“作业”标签。

作业上传与批改详情的处理中说明和错误留在表单旁，错误以危险色、13px文字显示，批改列表读取失败使用全站持久错误提示。错题删除后的提示可直接撤销，撤销恢复原学生的错题而保留当前正在查看的学生；反馈和学情报告删除需要站内确认，明确无法恢复。

学生档案头部的“更多”菜单集中放“编辑档案”和“删除档案…”。删除档案时必须输入完整学生姓名；确认框明确列出学生讲义、作业与批改记录（包括照片）、错题本、课后反馈和学情报告，这些内容会一起永久删除、无法恢复。取消或 Esc 不删除；删除当前学生后选中列表中下一位，没有下一位时选上一位，并同步地址栏。

学生档案的“定档”页签把这位学生的情况分成两半，顶部可选“全部 / 近 30 天 / 近 90 天”：

- **知识点（客观，来自作业批改）**：只统计开启“计入定档”的作业（布置的作业总是计入；直接上传的新作业默认计入，批改后可以在详情页切换），数据就是 `student_capability_evidence` 里的知识点证据。先写总题数和正确率，再按题型（选择、填空、解答……）各给一条对 / 部分对 / 错的比例条；下面按图谱的领域分组列出主题，主题按正确率从低到高排，点开看它下面的知识点。“在知识图谱里看”在同一标签页打开 `/knowledge-graph?student=`，直接叠加这位学生。
- **能力（主观，来自课后反馈）**：能力维度固定五项——粗心、计算能力、思维能力·逆向、思维能力·分析、思维能力·转化。老师上完课在这里写或说一段话（Mac 按两下 fn 听写，Windows 按 Win + H），选上课日期，点保存：原话照存，AI 把它对到五项能力，每条判断标出优势或短板，并且必须引用老师原话；引用对不上原话的判断丢弃，不做推断。话里其他要点（讲的内容、具体错误、学习习惯）作为关键词保留，也必须是原话里的词。“粗心”本身是短板，它好的一面写作“细心”，汇总里写“改善”。上方逐项汇总这段时间里被说成短板、优势的次数和最近一句原话。老师可以去掉某个判断或关键词、修改原话（改后清空旧判断并重新提取）、重新提取或删除。AI 没配置或读取失败时原话照样保存，标记“还没读出关键词”，可以稍后重新提取。存储：表 `student_observations`。

AI 写的批改报告仍然“不归因粗心或态度”；“粗心”只来自老师自己的判断。智能组卷读学生档案时，也读最近 6 条课后反馈（原话和读出的能力）和批改出的正确率最低的知识点。

## 学生档案 · 学情报告

给家长看的一段时间的学习情况。“学情报告”页签选起止日期（默认接着上一份报告，第一份或当天再做一份时是近 30 天），点“生成学情报告”：

- **数据快照**：生成时把这段时间的档案取出来存进报告——这段时间布置或批改过的作业（布置的作业按整份算交了几题、对错几题）、批改出的知识点和题型、课后反馈原话和读出的能力、新进错题本的题数。报告发出去以后档案再变，报告也不变；老师修改文字也不改数据。
- **AI 写文字**：只根据快照写总体情况、知识掌握、能力表现、下一步安排（2—4 条）和给家长的话。数字只能用快照里的；能力表现只依据课后反馈原话，可以转述老师说的“粗心”，不能从作业结果推断粗心、态度或用时；没有的数据直接说这段时间没有。日期按老师浏览器所在的时区写。AI 没配置或失败时，报告照样生成，文字先放数据摘要，提示原因，由老师补写。
- **修改与下载**：每段文字都能直接改，离开输入框就保存；作业、知识点（做过 2 题以上，正确率从低到高）、五项能力三张表来自快照，不能改。“下载 PDF”用本机 Tectonic 排版（版式与 IGCSE / A Level 批改报告相同），不能排版的设备可下载 TeX。历次报告列在左侧，可以删除。存储：表 `student_reports`。

## 多页作业完整性门槛

直接上传的作业逐页识别，每份作业使用 4 路并发读取页面。校内作业的题号、作答、批改符号、配图和坐标首先只从当前页一张图片识别，不能把相邻页一起交给模型决定本页题目清单。仅见小问号时保留小问号，不猜大题号；题意不完整的条目才额外参考相邻页补齐印刷条件。补全阶段的题号清单必须与待补全条目完全一致，服务端保留首次识别的页码、坐标、作答及老师符号，只接收补充的题意。PDF 顺序可能与印刷页码不同，不假定上一张一定是续题的前半页。IGCSE / A Level 沿用整卷跨页题号归并规则。

每页必须返回本页回执、页面类型和可见题号清单；题号清单与本页题目正文必须一一匹配。校内题号的 PDF 页码前缀还必须与作答起始页一致。提示词分别说明实际输入图片数与整份 PDF 页数。空白与不可读页面必须明确说明，不能当作遗漏忽略。旧版多图识别缓存不作为新规则下的完整性凭据，需要重新读取。

全页重读通过后，本次提交的题目列表、进度统计和批改范围以新回执的题号清单为准，不把本次未识别到的旧题号补回列表。旧题目、旧批改与修订证据仍保留；被撤回题号对应的本次错误发生记录停用，已经收录的错题在没有其他有效错误记录时转入历史，避免错页记录继续影响学生档案。

成功回执按提交、页面及邻页图像指纹保存。重试恢复已成功页面，换图后相关回执失效。没有所有当前页面的有效回执时，不允许确认模板、发布结果或显示整份完成。全部页面读取并完成跨页题汇总后，老师已标记的题目先保存判定，题意不完整的题目先记录为待处理。其余题目按批执行“解题→核验→批改”，一批核验完成就立即批改，不再等待其他批次；整份作业的模型请求共用最多 4 路并发，不按阶段叠加。每批最多 6 题，剩余少量题目均衡分配到最多 4 路（例如 6 题分成 2、2、1、1）；自动重试时批次上限依次缩为 3 题、1 题。一个批次失败后其余独立批次继续完成，再由原队列重试未完成部分。返回题号必须与请求题号完全一致，缺题或重复题号视为不完整输出并停止任务。解题成功即保存答案检查点；现有 reference_fingerprint 使用 pending: 前缀表示尚未核验，reference_verified 保持 0，进度不将其计为已准备好。核验完成后才保存正式指纹；中断重试只补核验，题干、配图条件或参考答案改变则重新生成。已保存的本轮判定不会重复批改。部分结果可实时查看，整份作业仍须全部处理结束并通过页面完整性检查后才发布和归档。不可核实的题目明确保留为待处理，不进入错题本。上游服务失败时队列自动重试，等待重试期间提交仍是“批改中”并显示重试说明，不允许手动重新批改，避免同一份作业同时跑两次、重复计费；用完重试次数才标记为处理失败。页面里找不到这份作业的题、或题数超过上限这类由原件决定的错误不重试，直接标记处理失败。

2026-10-08 的真实 API 对照使用固定 16 个混合请求（读页、解题、核验、批改各 4 个），保持模型、输入和单次尝试一致，不写回作业。4 路有效基准为 13/16、178.3 秒；6 路两轮合计 28/32、每轮平均 165.7 秒；8 路两轮合计 27/32、平均 135.3 秒，两轮均出现 429 限流。4 路第二轮出现独立连接检查亦能复现的传输异常，原始记录保留但不计入速度对照。该小样本不能代表长期容量或数学准确率，默认仍保持 4 路；6 路可作为后续持续观察的候选，不能仅凭耗时直接启用 8 路。

历史提交缺少新回执时，结果页标记“已有结果不完整”，可以使用“补全页面并重新批改”恢复；修复前逐题批改保留在修正历史中。完整性回归覆盖“只返回开头页面”“错误页码”“题号清单与正文不匹配”“明确空白/不可读页”“跨页续题”“分批结果缺题”和“中断后按页恢复”。此门槛防止漏处理页面却发布完成；模型对单个字迹、公式或题意的判断仍需通过原卷证据与教师修正核实。
