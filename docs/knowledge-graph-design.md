# 知识图谱：点云浏览、教师编辑与数据链路

## 定位

知识图谱是题库、讲义、作业和学情的共同底座：题目标签、作业证据、错题归因都指向同一组稳定的知识点编号（key）。页面 `/knowledge-graph` 同时承担两件事：

1. **浏览**：在一张点云里看清几百到上千个知识点、任意知识点的全部前置链和接下来解锁的内容；叠加某个学生的证据，看掌握层级和薄弱环节。
2. **编辑**：教师在可视化背后调整内容——知识点、学会的标志、前后关系、识别别名、教材定位、领域颜色——以草稿保存，发布后生效。

视觉参照 withmarble.com/curriculum（只借鉴设计，不使用其数据）：整页固定深色、全屏点云、浮动玻璃面板，不跟随网站浅/深色切换。

图谱不追求囊括所有知识点，而是贴合具体的教材和课程，所以有多张、可以切换（见“可切换的图谱与课程图谱”）。题库自动打标签和作业证据用的是人教版通用图谱。

## 可切换的图谱与课程图谱

- **图谱列表**写在 `lib/knowledge-graph-course.mjs` 的 `KNOWLEDGE_GRAPHS` 里：`cn-math-junior`（人教版通用，下文其余各节说的都是它）和 `sz-innovation-course`（深圳创新班课程）。页面左上角原来的标题位置是切换下拉，地址 `?graph=` 记住当前图谱，切换时先保存草稿再整页打开另一张。接口都带 `graph` 参数（GET 用查询参数，写入放在请求体），不带时就是人教版通用图谱，所以打标签、学情和线上同步都不受影响。每张图谱各有自己的草稿、修订号和版本记录（同一组表，按 `graph_id` 区分）。
- **课程图谱的节点来自默认深圳创新体系的讲义**：一讲是一个主题（编号 `lesson:<讲义id>`），讲里的一个知识模块是一个知识点（`module:<模块id>`），编号跟着讲义和模块走，改名不变号。领域固定为函数、几何、代数、数论、数学思想，专题库的自定义目录及改名不改变这些领域。年级层是初一、初二、初三，同一年级内按该体系的单元、课次顺序由下往上（初始为暑假 → 秋季 → 寒假 → 春季）。自定义体系独立保存，其模块不会混入这张图谱。版本 1 是只有五个领域和三个年级的空图谱。
- **图谱自己只保存**领域归属、前后关系、描述和学会的标志。每次读取（浏览、编辑、发布）都先用 `syncCourseGraph` 按当时的课程体系同步一遍：讲义改名、增删模块、调整课次，图谱立刻跟着变；新加的一讲先放在前一讲的领域里；讲义里删掉的讲次或模块，已经发布过的保留为“已停用”（历史可追溯），没发布过的直接去掉，连在它们上面的关系一并去掉。
- **编辑**：课程节点的名称、年级、所在讲次只读，旁边是“在讲义中修改”；可以改所属领域、描述、学会的标志和前后关系。“＋ 新增”只能加领域（讲次和模块在讲义里加），也没有停用、合并、教材定位和识别别名。新节点的编号前缀取领域编号的前缀（课程图谱是 `course`），不会和讲义来的节点混淆。
- **浏览**：课程节点的卡片列出讲义里这个模块（或这一讲）有几道例题、练习、变式，以及几道小测、作业题考查它，并有“打开讲义”，在新标签页打开讲义编辑页并滚到这个模块（`?module=`），左侧题库的加入位置也指向它。
- 课程图谱只在本机使用，不随“发布公共资源库”同步到线上：它依赖的讲义不在线上。

## 怎么读这张图

- **漏斗形点云**：高度就是学习顺序——七年级在下、九年级在上，同一年级内按教材章节由下往上；越往上漏斗越宽。左侧标出年级。
- **颜色**：每个领域占一块扇区、一种主色；同一领域的不同主题是同色系的深浅。左下图例点击可按领域筛选，也可只看某个年级。
- **大小**：圆点越大，说明它支撑的后续知识点越多（越基础）。带环的大圆点是主题，实心小点是知识点。
- 默认不显示文字。悬停看名称、所属主题与“学会的标志”；顶部搜索按名称和别名定位，输入时匹配的点会在图上标出。
- **点选（链路视图）**：这个知识点的完整逻辑链会从点云中浮出，铺满屏幕中的空闲区域，变成一张分层图。
  - **排布**：前置在下、后续在上，每个点都有名称。左侧标出“前 n 层 / 当前 / 后 n 层”，层号按到当前点的最长路径计算，所以每条关系线都朝上。
  - **关系线**：已经能由更长路径推出的“捷径”关系默认隐藏，悬停某个点时才和它的其他关系一起亮出，便于看清谁依赖谁。前置一侧的线用领域色，后续一侧用白色。
  - **范围**：前置一直显示到起点；后续按步数由近到远先显示约 40 个，卡片里可以“全部展开”。图太长时可以滚动或拖动查看，并有提示。
  - **跳转**：点图中的圆点或名称可以沿链跳转（带返回），点空白处收回点云。卡片右上角可以切回“点云”，在漏斗中看它的位置。
  - **卡片**：右侧卡片显示“前置 N 个 / 后续 M 个”、直接前置与直接解锁列表。
- 空闲时缓慢自转（悬停、拖动、选中时停止）；系统开启“减少动态效果”时不自转、不播放生长动画。手机上卡片变成底部抽屉。
- **叠加学生**：圆点改为掌握状态色（需关注 / 形成中 / 稳定 / 证据不足；未检测为暗灰），有证据的点会发光。左侧“学情诊断”给出建议先补：沿前置关系追溯，自身薄弱但前驱都不薄弱的点才是根源，按影响的后续数量排序；并列出各年级稳定数。地址带 `?student=`（学生档案 · 定档的“在知识图谱里看”）时打开就叠加这位学生。
- 布局由数据计算（`layoutKnowledgeFunnel`），不存坐标；改名称、描述不会重排，增删知识点或关系、调整顺序时自动重排。

## 层级与字段

| 层级 | 说明 | 示例 |
| --- | --- | --- |
| 领域 domain | 扇区与主色，不参与前后关系 | 数与代数 |
| 主题 topic | 教材章级节点，带环的大圆点 | 一元二次方程 |
| 知识点 point | 细粒度节点，题目标签的主要落点 | 配方法 |

知识点字段：名称、年级、所属主题、顺序、一句话描述、**学会的标志**（`mastery`，一句可检测的“能……”）、识别别名、教材定位。

关系只有两种：`prerequisite`（前置，hard）和 `supports`（支撑，soft）。校验规则：引用必须存在、不能自环、上下级之间不连线、整体必须是 DAG（出现环会给出“形成循环：A → B → A”）。

## 规模

- 渲染是一块 Canvas 2D 和手写透视投影，没有 WebGL，也没有逐节点 DOM。默认的边按景深分档批量绘制，只给焦点和少量邻居画文字。
- 实测（无头 Chrome，1600×1000）：414 个知识点和合成的 1500 点 / 4000 边在自转、悬停、聚焦时都稳定在 60 fps，每帧脚本约 1 ms。整页客户端代码 gzip 后约 33 KB。
- 上限：2500 个节点、8000 条边、草稿 1.9 MB（D1 单行 2 MB 以内）。
- 编辑面向上千节点：
  - 目录按领域展开，主题默认折叠。
  - 选中主题后可以批量粘贴知识点（`名称｜学会的标志｜别名、别名`，可选“按顺序连成前置链”）。
  - 整份 JSON 可以从“更多 → 导入 JSON”载入为草稿，先预览相对已发布版本的改动；文件里缺少的已发布节点自动保留为“已停用”。

## 细粒度初中数学草稿（待审核）

- **生成方式**：`data/drafts/china-math-junior-fine.source.mjs` 是作者源，每行一个知识点：`名称｜描述｜学会的标志｜别名｜直接前置`。运行 `node scripts/build-knowledge-graph-draft.mjs` 生成 `data/drafts/china-math-junior-fine-draft.json`；加 `--check` 只做校验。
- **规模**：
  - 4 个领域、33 个主题。新增二元一次方程组、整式的乘法、锐角三角函数、投影与视图四个主题，原来的“旋转与投影”拆成“旋转”和“投影与视图”。
  - 414 个知识点、652 条关系（635 条前置、17 条支撑）。
- **来源说明**：这份草稿由 AI 按人教版七至九年级的章节结构整理，没有逐条对照教材原文。主题级填写了人教版册次与章名，状态保持“待校准”；知识点暂时继承所属主题的教材定位。发布前需要教师逐项审核。
- **兼容性**：
  - v1 的全部编号保留。改名的主题把旧名加入别名。
  - v1 的旧别名如果已经被细分知识点承接，就移交给该知识点，否则留在主题上，保证已有题目标签继续解析。
  - `tests/knowledge-graph-draft.test.mjs` 逐个检查这些规则，并检查提交的 JSON 与作者源的构建结果一致。
- **审核流程**：编辑 → 更多 → 导入 JSON → 选择该文件 → 预览改动 → 载入为草稿 → 在目录或点云中逐项审核修改 → 发布。

## 草稿、发布与版本

- **存储**：图谱版本存于 D1，`knowledge_graphs` 保存发布指针、唯一的共享草稿和修订号，`knowledge_graph_versions` 保存不可变快照。v1 是内置 JSON 种子，迁移前或空库时自动回退到它。
- **保存与校验**：编辑即自动保存草稿，采用乐观并发：用旧修订号写入会返回 409，不会覆盖另一窗口的修改。草稿允许暂时不完整，**发布时**才强制校验。可以撤销、重做。
- **名称与提示**：页面大标题直接使用切换器里的当前图谱名称（“人教版通用”或“深圳创新班课程”），不从文档标题裁切；图谱文档及JSON导出的标题不改。操作结果复用全站左下角提示条，并沿用图谱的深色语义配色；成功六秒后消失，停留或聚焦时暂停，出错保留到手动关闭。放弃草稿、载入历史版本、停用或删除节点、合并节点四类操作保留原浏览器确认，其他图谱对话框和草稿流程不变。
- **已发布的 key 永不删除**：只能停用（archived）或合并（mergedInto）。合并会转移关系、下级知识点和别名，历史证据和题目标签自动归到合并目标。
- **版本恢复与导入**：版本记录可以把任意历史版本载入为草稿，导入 JSON 也一样。载入后，后来发布过的知识点作为“已停用”保留，引用不会断。
- **权限与同步**：与公共题库一致，只有 localhost 本地管理员能编辑。点“发布公共资源库”时先同步已发布的图谱，再同步题目，线上不会出现无法解析的标签；线上按内容哈希判断是否需要更新。

## 数据链路（现在与后续）

```
知识图谱 key ──► 公共题库题目 taxonomyKeys ──► 讲义（按课程/讲次选题）──► 作业
      ▲                                                                    │
      └────────────── 学生证据（知识点证据同时计入主题和领域）◄───────────────┘
                                                                           │
                                                   错题本：题库题引用快照 / 未收录题 OCR 快照
```

- **自动打标签**：题目保存时用**已发布图谱**的名称和别名自动打标签，所以在图谱里补充别名会立刻改善打标签。下一步是让题目编辑器直接从图谱选择知识点，显式选择的 key 优先于自动识别。
- **学生证据**：学情叠加和“建议先补”读取 `student_capability_evidence`。开启“计入定档”的作业经 `replaceSubmissionCapabilityEvidence` 按知识点、主题、领域写入证据。直接上传的新作业默认开启，批改详情页可以事后切换；打开会补写全部已发布提交，并以各自提交时间（缺失时用创建时间）记录证据，关闭会移除该作业证据。旧作业保持原选项，由老师自行决定（见 `docs/homework-product-design.md`）。
- **错题来源**：
  - 已收录题：错题本保存题库题目快照并记住来源题号，不复制进题库。
  - 未收录题：用题目收录的 OCR 能力生成快照，**只写入该学生的 `student_wrong_questions`**，绝不进入公共题库或“我的题库”。精选题库只由教师主动录入或发布维护。
- **后续模块**：讲义编撰、课程与学生分班只需要引用题目 ID 与图谱 key，不需要改动图谱结构。

## 代码位置

- `lib/knowledge-graph-course.mjs`：图谱列表、课程图谱的种子和 `syncCourseGraph`、课程节点编号与讲义链接。`lib/server/handouts.ts` 的 `readCourseLessons` 按教学顺序读出课程体系的每一讲、每个模块和各段题数。

- `lib/knowledge-graph-core.mjs`：规范化、校验、索引（前驱/后继闭包、标签识别、合并重定向）、漏斗布局与中心度、链路分层（`layoutKnowledgeChain`：最长路径分层、捷径分离、重心排序）、配色深浅、差异、学情诊断。
- `lib/knowledge-graph-edit.mjs`：草稿编辑操作，全部是纯函数，包括新增、批量添加、改名与学会的标志、关系、停用、合并、教材定位和整份导入。
- `lib/server/knowledge-graph.ts`：已发布版本缓存、草稿与发布、版本恢复、题库覆盖统计、线上同步。
- `app/knowledge-graph/`：页面、样式、编辑会话（自动保存、撤销/重做）。
- `app/components/knowledge-graph/`：
  - `cloud-renderer.ts`：Canvas 点云引擎（投影、绘制、拾取、相机），以及链路视图的排版（换行、对齐、适配、滚动）和过渡动画。
  - `GraphCloud.tsx`：挂载画布与悬停卡片。
  - `NodeCard.tsx`：选中卡片。
  - `GraphLegend.tsx`、`GraphSearch.tsx`：图例与搜索。
  - `GraphOutline.tsx`、`NodeEditor.tsx`：编辑目录与编辑器。
  - `GraphDialogs.tsx`：发布、版本记录与导入对话框。
  - `StudentDiagnosis.tsx`：学情诊断面板。
- 测试：
  - `tests/knowledge-graph-core.test.mjs`：纯逻辑，包括漏斗布局与 1500 点规模。
  - `tests/knowledge-graph-course.test.mjs`：课程图谱的生成与同步（改名、领域继承、删除后停用、关系去留）。
  - `tests/knowledge-graph-draft.test.mjs`：细粒度草稿。
  - `tests/knowledge-graph-e2e.test.mjs`：双 Worker 场景，覆盖草稿冲突、发布校验、版本恢复、打标签和线上同步，以及课程图谱的发布和随讲义同步。
