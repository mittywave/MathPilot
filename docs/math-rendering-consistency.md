# 数学公式稳定性修复：第一版与测试说明

## 范围

本版对应优化建议文档的第一版 PR 范围：统一新识别结果的显式 LaTeX、共享解析器和网页渲染器、识别行内与独立公式、取消嵌套分式的额外放大、统一公式相对于正文的字号。

不修改数据库结构，不批量改写历史题目，不触碰 API Key、注册权限、发布地址或原作者仓库。没有增加额外 AI 请求。

## 代码变化

- `lib/math-output-contract.ts`：截图、批量录入及 Answer Studio 共用公式输出规则。要求 `$...$` / `$$...$$`、正确 JSON 转义、普通 `\frac`，禁止模型为了排版输出字号命令；不得求解、补写或偷偷纠正原件。
- `lib/math-text-core.mjs`：唯一的解析实现，区分 `$...$`、`$$...$$`、`\(...\)`、`\[...\]`；处理转义美元符号；保持显式公式内部结构和多行内容。
- `lib/math-text.ts`、`lib/answer-studio-math-text.ts`：兼容入口，转发到同一个实现。保留历史 Unicode / 未加定界符的公式兼容逻辑，避免旧题目突然不显示；新识别结果依赖显式定界符。
- `MathText` 与 `StudioMathText` 共用组件：将 `display` 传给 KaTeX 的 `displayMode`；语法错误显示“公式待核对”，保留原文，不再静默降级。
- 含普通 `\frac` 的公式中，网页渲染器将 `cases` 按 KaTeX 原生的 `dcases` 样式排版，避免方程组单元格重置为行内样式后把第一层分子、分母缩到正文的 70%。行内和独立公式采用同一规则，适用于题干、选项、答案、解析和讲义公式预览；上下标、真正嵌套的分式及显式 `\tfrac` 继续按原生数学层级缩小。只调整网页显示，不改写题库源码、Word 导出或矩阵等其他环境。回归测试覆盖两行方程、不等式组、带条件的分段式、嵌套方程组及错误环境边界。
- 旧识别文本中，公式外残留的字面 `\n` / `\r\n` 在自动解析和网页分行时还原成真实换行，避免普通题干误入 KaTeX；已保存题目无需重新识别。后面紧跟大写字母时（如选项 `\nA.`）同样换行，除非去掉 n 后是命令（`\nRightarrow` 等否定箭头）；后面紧跟小写字母时可能是命令（`\neq`、`\newcommand`），保持原样。显式公式、正常 LaTeX 命令、代码示例、文本参数、路径及重复反斜杠保持原样，严格解析模式不作此兼容转换；不改写数据库，真正的公式语法错误仍显示核对提示。文件转录在规范化识别结果时就做这项还原，存下的草稿、公式检查和 Word 段落看到的都是真实换行；每次运行（包括生成 Word）都会重新规范化，旧草稿也会被修复。
- 模型只写一个反斜杠时，以 b、f、n、r、t 开头的命令（`\therefore`、`\frac`、`\because`、`\right`、`\ne`）恰好也是合法的 JSON 转义，解析后变成控制字符加命令名的后半截，∴ 显示成“herefore”。`restoreDecodedCommands`（`lib/math-source.mjs`）把它们还原：只还原公式能力表里已有的命令，其余保持原样、照常提示核对；退格、换页在任何位置还原，制表符、回车只在显式公式内还原；换行可能是真实换行，只在公式内、本行前面有内容时还原，`\ne` 只在行内公式里还原，不碰 `e^x`、环境换行和公式外正文。AI 引擎解析模型 JSON 时就做这项还原，新结果存下的就是正确命令；`splitMathText` 在网页显示和 Word/PDF 导出前再做一次，已保存的批改错因、作业题目、错题本和题库不改写数据库也能正确显示；文件转录的规范化复用同一函数，取代原来逐个列出的命令。
- `app/math-typography.css`：只控制 KaTeX 根元素的相对字号，不覆盖其内部上下标和分式字号。较长的独立公式可在自身容器滚动，不靠整式缩小塞进页面。
- `lib/word-math-sizing.mjs`：不按分式层数放大。2026-10-05 起，行内公式最外层分式的分子、分母设为 28 半磅（正文 21），抵消 Word 对行内分式的缩小，与菁优网导出的 Word 一致；嵌套分式、独立公式和导入文件自带的字号不变。网页端同理：含分式的行内公式以 `\displaystyle` 渲染（`lib/math-render.ts`）。只由行内公式组成的一行（如“$+6$, $0.75$, …”）不再居中，只有 `$$…$$` 或未加定界符的整行算式才居中。
- `lib/export-word.ts`（2026-10-05，按真实 Word 渲染校准）：简单式子（字母、$v_0$、$x^2$、$a=6$、$∠A=30°$、$1\text{ cm}$、填空横线）按菁优网 Word 的做法写成正文：Times New Roman 斜体字母、正体数字、两数之间用全角＝＋﹣＜＞，正负号紧贴数字；分式、根式等有结构的式子仍是可编辑的 Word 公式。正文行距为“最小值 23.4 磅”（菁优网实测值），不随本机宋体变化，含分式的行自动撑高。
- 组卷和讲义的 Word 答案解析复用网页的 `splitMathLines` 安全分行：每个非空源行导出为独立段落，递等式的每一步保留换行；“解析：”只出现在无 `【解答】` 等标签的首段。兼容真实换行及旧数据中的字面 `\n`，不拆开完整公式内部的多行 `aligned` / `cases` 环境；有原始 DOCX XML 的解析继续保留原版结构。该规则同时适用于文末答案和逐题答案，不改写题库数据。
- 解析中以等号开头、独占一行的递等式步骤统一使用原生 Word 公式，并明确设置数学段落 `m:jc=left`，使分式步骤和简单算式的等号纵向对齐。只设置普通段落的左对齐不能覆盖 Word 的数学居中默认值。若解析第一行就是递等式，“解析：”单独成段，避免文字挤入独立公式；行内公式及导入的原始 DOCX 排版沿用原规则。
- `lib/math-omml.ts`（2026-10-15）：成对的 `(`、`[` 仍转成随内容伸缩的 Word 括号（含 `(a,b]` 这类半开区间）；同一段公式里找不到 `)`、`]` 的括号按普通字符输出，与 KaTeX 一致。识别结果常把填空横线放在公式外，一对括号于是跨两段公式，例如 `$\sqrt{3}=($________$+$________$\sqrt{3})^2$`，此前 Word 导出会报“公式 )] 未闭合”，整份失败。多余的右花括号、未闭合的 `{` 和 `\sqrt[` 仍报错。每个括号位置只尝试配对一次，括号再多也不会成倍变慢。
- `lib/answer-studio-rich-text.ts`：正文文字与已有 Normal / StudioAnswer 段落样式一致，统一为 22 半磅（11 磅）。

公式可能因为分式、根式而自然增高，上下标也仍会缩小；这不是错误。本版取消的是额外、与语义结构无关的放大。

## 人工验收清单

1. **已有题目**：刷新旧题，确认题干、选项、答案、解析没有丢字；Unicode 数学符号、填空横线的既有兼容行为没有回退。
2. **重新识别**：重新上传数列、抛物线和嵌套分式样本。新 Prompt 只影响新请求，不会重写旧识别文本。
3. **两种网页入口**：在题库和 Answer Studio 比较相同的行内/独立公式。相同正文上下文下主体字号一致，独立公式自然展开；指数不是被强行变成正文字号。
4. **报错提示**：输入 `$\frac{1}{$`，确认“公式待核对”提示和原始表达式可见。
5. **Word 导出**：从真实网页重新导出 DOCX，检查分式仍为可编辑公式，嵌套分式不再因为层数被整体改成 13/15 磅；在实际使用的 Word/WPS 中检查分页、公式裁切与图片。旧的已导出文件不会自动变化。
6. **移动端与长公式**：检查窄屏下能完整读取长式，页面不被公式撑宽，横向滚动只发生在公式自身容器。

可用于手工录入的样例：

```latex
设 $P\left(m,-\frac{1}{8}m^{2}+\frac{1}{2}m+4\right)$。
$$d=\frac{\left|-\frac{1}{8}m^{2}+\frac{3}{2}m\right|}{\sqrt{2}}$$
$$\sin\angle PAD=\frac{\frac{5\sqrt{2}}{4}}{\frac{25}{2}}$$
```

## 明确的边界

- 语法能渲染不代表数学识别正确，例如把减号识别成加号仍可能通过 KaTeX。须对照原图校对。
- 保留原文显式写出的 `\dfrac` / `\tfrac`；不擅自改写历史内容。行内分式按正文大小显示是渲染规则，不改写存储的文本。
- 本版没有实现保存前的统一强制拦截、局部裁图二次识别、公式级置信度、并发识别队列，这些属于后续阶段。
- Word 原生公式转换器的命令支持范围没有在本版全面重写；网页能显示的全部 LaTeX 不保证都能导出为原生 Word 公式。含复杂环境或跨物理行公式的 Word 导出须重点验收；新 Prompt 要求每个公式保持在一个逻辑文本行，以适应现有导出流程。
- 旧 DOCX 原样导入通道保留作者原本设置的字号；不会为了视觉统一破坏原始版式。
